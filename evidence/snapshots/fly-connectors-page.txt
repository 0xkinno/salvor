        <h2 class="font-heading text-3xl md:text-4xl text-navy mb-8">
          What Connectors actually do
        </h2>
        <p class="text-lg text-gray-700 mb-8">
          From inside a Sprite, calling an external API looks like calling a plain HTTP endpoint with no auth attached:
        </p>
        <pre class="bg-gray-900! text-gray-100 p-4 rounded-lg overflow-x-auto text-[0.9375rem] font-mono leading-relaxed mb-8"><code class="bg-transparent! border-0! p-0!">curl https://api.sprites.dev/v1/gateway/github/user/repos</code></pre>
        <p class="text-lg text-gray-700 mb-8">
          See? No token in that request. You select which Sprites get access to each Connector. The Connector injects the real credentials, and proxies the call. The response streams back as if the Sprite had called the API directly. What the Sprite never gets is the key: that stays in the control plane (encrypted) and is attached to the request on the way out.
        </p>
        <p class="text-lg text-gray-700">
          This is why you can safely run agents and their integrations (along with the code they generate) in Sprites. An agent that never holds a raw token can't leak it, log it, or ship it off in a curl to somewhere it shouldn't. You get the reach of a fully credentialed client with none of the exposure.

        <h2 class="font-heading text-3xl md:text-4xl text-navy mb-12 text-center">
          Frequently asked questions
        </h2>
        <div id="faq-list" class="space-y-4">
          <details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>What are Fly.io Sprites Connectors?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">Connectors let a Fly.io Sprite call external APIs like GitHub, Slack, and OpenRouter without holding the credentials. You set up a Connector once at the organization level, and it injects the stored credentials and forwards each request, so a Sprite reaches your real services while the raw token stays in Fly.io&#39;s control plane.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>Do I have to put API keys inside a Sprite to call external services?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">No. That is the whole point of Connectors on Fly.io. A Sprite calls the Connector URL with no token attached, and the Connector adds the credentials on the way to the provider. The key is never written to the Sprite, so an agent or the code it runs cannot read or leak it.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>What services can I connect through Fly.io?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">GitHub and Slack connect over OAuth, OpenRouter connects for model access with a key you supply, and any other HTTP API connects as a custom Connector using a base URL and token. S3-compatible object stores connect the same way. Each becomes a named Connector that authorized Sprites on Fly.io can use.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>Can I call LLMs through Connectors with OpenRouter?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">Yes. OpenRouter is a first-class Connector on Fly.io, and it reaches a large catalog of models through one OpenAI-compatible endpoint. You connect it with your own OpenRouter key, and your agent calls models through the Connector while the key that pays for them never enters the Sprite.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>How do Connectors know which Sprite is calling?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">Each Fly.io Sprite has its own platform-issued identity, and Connectors authenticate the request by that identity rather than by a key in the request. From there they map the Sprite to its organization and find the matching Connector, so there is nothing for the Sprite itself to present or store.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>Can I limit which Sprites use a Connector and which endpoints they can hit?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">Yes. On Fly.io every Connector is default-deny, and you grant access to specific Sprites by label or name prefix, or to all of them explicitly. You also scope the allowed request paths with allow and block patterns, so a Connector can permit one endpoint, like posting a Slack message, and refuse everything else.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>Do Connectors handle OAuth token refresh?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">Yes. Fly.io Connectors refresh expiring OAuth tokens on their own, so a Connector keeps working without anyone rotating credentials by hand. Your Sprites keep calling the same Connector URL, and the fresh token is injected for them each time.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>How does an agent find out what it can reach?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">A Fly.io Sprite calls the Connectors list endpoint, which returns the Connectors that are ready to use, each with its base URL, granted scopes, and a ready-to-run example, plus the providers still available to set up. When more permissions are needed, the response includes a URL to request additional scopes.</p>
          </details><details class="group rounded-2xl border border-gray-200 bg-white p-6">
            <summary class="flex cursor-pointer list-none items-center justify-between gap-4 font-heading text-lg text-navy">
              <span>Can I connect an API that isn&#39;t built in?</span>
              <span class="shrink-0 text-2xl leading-none text-purple-600 transition-transform group-open:rotate-45">
                +
              </span>
            </summary>
            <p class="mt-4 text-gray-700 leading-relaxed">Yes. Alongside the built-in providers, Fly.io supports a custom Connector where you supply a base URL, a token, and how the token should be sent, which turns any HTTP API into something your Sprites can call. S3-compatible object stores are supported the same way, so most services a Sprite needs can go through Connectors.</p>
          </details>
